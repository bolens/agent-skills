# Modern web targets

Default to the latest stable browser features and maintained stable framework/tool versions. Target current Chromium, Firefox, and Safari engines across the relevant desktop/mobile platforms, unless the user or repository explicitly narrows that scope. Backward compatibility with old browsers, runtimes, or dependency versions is required only when explicitly requested or part of the existing product contract.

Verify current release documentation and feature/subfeature support before implementation. Do not freeze this skill to a dated browser percentage, framework major, or support label. Newly available Baseline features can be suitable; there is no default requirement to wait until they are widely available. A Baseline badge does not establish webview or assistive-technology behavior. See [Baseline definitions](https://developer.mozilla.org/en-US/docs/Glossary/Baseline/Compatibility).

Latest stable does not mean experimental flags, preview/canary packages, or one-engine-only essential behavior. Where current engines differ, select a supported native alternative or a focused capability check and fallback. An optional enhancement may be omitted in an engine that lacks it if core functionality remains intact. Report that limit. Avoid a legacy polyfill bundle, old syntax target, duplicate implementation, or framework pin merely for hypothetical older users.

For new projects and newly selected dependencies, prefer current stable versions verified from primary sources. In an existing application, inspect the installed version and adopt current APIs through a scoped, tested update when the task calls for it. Do not paste an incompatible API into an older runtime or upgrade the whole stack during an unrelated visual repair. Use [dependency triage](../../triage-dependency-updates/SKILL.md) for actual upgrades and preserve the chosen framework unless migration is in scope.

Inspect Browserslist, transpiler targets, CSS transforms, polyfill imports, runtime floors, and lockfiles when compatibility work is authorized. Make them agree with the declared current target matrix. Remove legacy-only compatibility code when its covered targets are no longer required and relevant checks pass. Retain server-rendering correctness, loading/error recovery, font fallbacks, semantic controls, keyboard access, and reduced-motion behavior: these solve current-user needs rather than historical browser support.

Test relevant features in current target engines. Device/viewport emulation within Chromium does not prove Firefox or WebKit compatibility. Record browser/tool versions, native features used, explicit legacy exceptions, executed checks, and unavailable coverage. Modern targeting does not relax security, accessibility, or functional verification.
