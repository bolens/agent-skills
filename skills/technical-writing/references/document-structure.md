# Document structure

Use Diátaxis as a diagnostic, not a purity test. Identify the reader's main need, then keep the document centered on it.

## Tutorial

Teach through a sequence that produces visible results. State what the reader will build. Give expected output at useful checkpoints. Keep explanation short and link to deeper material.

## How-to guide

Help a competent reader complete a concrete task. Lead with prerequisites and actions. Include decision branches when the task requires judgment. Keep background out of the main path.

## Reference

Support lookup. Mirror the structure of the code, command, API, or configuration. State accepted values, defaults, constraints, errors, and examples without persuasion.

## Explanation

Answer a bounded "why" question. Cover constraints, alternatives, history, and trade-offs. State a reasoned view when evidence supports one.

Documents may contain supporting material from another mode. A short option table can help a how-to. A compact example can clarify reference material. Split content only when the secondary material interrupts the reader's main job.

Use sentence-case headings. Task headings use verb phrases. Concept headings use noun phrases. Number sequences and use bullets for unordered sets.
