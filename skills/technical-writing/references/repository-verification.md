# Repository verification

Inspect the code and project instructions before documenting behavior. Do not rely on plausible names or remembered defaults.

Verify:

- symbols, paths, commands, flags, and configuration keys
- defaults, limits, supported versions, and error behavior
- sample output and procedure results
- generated counts, trees, and tables
- the repository's established terminology and documentation location

Run the cheapest authoritative command that proves each material claim. Include regeneration commands for committed generated material. If verification is impossible, state the gap precisely and avoid presenting an inference as a fact.

Do not change code to make documentation true unless the user also authorized an implementation change.
