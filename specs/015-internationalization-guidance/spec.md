# Internationalization and standards guidance

## Contract

Add a locally authored internationalization skill for locale-dependent application
behavior. Translation-only copy requests, localized SEO, and isolated accessibility
defects retain their existing owners. Support web applications and reuse native
runtime locale facilities for other clients without assuming browser APIs exist.

Keep conditional details in references. Connect existing accessibility, forms,
design-system, SEO, and browser-evidence workflows without making every task an
internationalization audit. Strengthen content clarity, privacy, and interrupted
workflow recovery in existing skills. Standards sources guide the applicable
contract, not an unsolicited certification or migration.

## Acceptance

- Locale negotiation, catalogs, plurals, formatting, RTL, Unicode, international
  input, and deterministic tests have actionable guidance and primary sources.
- Source selection distinguishes specification status, implementation support,
  registries, advisory guidance, and actual conformance evidence.
- Existing skills expose the relevant handoffs and retain scope and authority.
- New skill metadata, provenance, installation targets, and references validate.
- Walkthroughs cover locale switching during an unsaved form, RTL user content,
  ambiguous save failures, privacy-sensitive telemetry, and a nearby excluded task.

No new runtime, translation service, background automation, or helper is needed.
