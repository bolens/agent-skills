# Obscura source audit

Audited [Obscura](https://github.com/h4ckf0r0day/obscura/tree/a1e09de68c7617b8079fbb1661b0548c501971c1)
at `a1e09de68c7617b8079fbb1661b0548c501971c1` on 2026-09-05.
Decision: refine the existing CLI browser evidence workflow with verified
backend constraints and comparison practices. Keep Obscura optional until a
task demonstrates a benefit and its required capabilities pass fixtures.

## Findings that affect adoption

These are findings about using the inspected revision for this collection's
workflows. Source reasoning is distinguished from execution below.

1. **P2: successful CDP responses can falsely suggest emulation coverage.**
   [`domains/emulation.rs`](https://github.com/h4ckf0r0day/obscura/blob/a1e09de68c7617b8079fbb1661b0548c501971c1/crates/obscura-cdp/src/domains/emulation.rs#L61)
   implements device metrics and background overrides, acknowledges touch
   emulation without applying it, and returns success for other methods.
   `Emulation.setEmulatedMedia` therefore reaches a successful fallback.
   [`dispatch.rs`](https://github.com/h4ckf0r0day/obscura/blob/a1e09de68c7617b8079fbb1661b0548c501971c1/crates/obscura-cdp/src/dispatch.rs#L804)
   also acknowledges whole diagnostic domains without implementation. A client
   connection or resolved command cannot prove reduced motion, theme, touch,
   or performance instrumentation. High-confidence source finding, not a live
   protocol reproduction. The local workflow now requires observable probes
   and keeps supported browsers as acceptance targets.

2. **HTTP MCP needs explicit control-session ownership.**
   [`http.rs`](https://github.com/h4ckf0r0day/obscura/blob/a1e09de68c7617b8079fbb1661b0548c501971c1/crates/obscura-mcp/src/http.rs#L181)
   creates one `BrowserState` before accepting clients. All connections use it.
   The request handler performs optional Origin filtering, not client
   authentication. The unset allowlist accepts every Origin, and configured
   allowlists still accept requests without Origin. The original filter was
   compiled and exercised in isolation: all three behaviors were confirmed.
   This does not establish a live browser exploit. Use a task-owned stdio
   process or an explicitly isolated, access-controlled HTTP session. Loopback
   binding is useful but does not supply session separation or authentication.

3. **Raster PDF output cannot establish semantic document requirements.**
   [`domains/pdf.rs`](https://github.com/h4ckf0r0day/obscura/blob/a1e09de68c7617b8079fbb1661b0548c501971c1/crates/obscura-cdp/src/domains/pdf.rs#L147)
   rejects several unsupported print options but accepts a tagged-PDF request
   while returning capability metadata that tags are unavailable. The
   [`browser PDF implementation`](https://github.com/h4ckf0r0day/obscura/blob/a1e09de68c7617b8079fbb1661b0548c501971c1/crates/obscura-browser/src/pdf.rs)
   rasterizes and slices the print layout with pixel, page, and output limits.
   This is a disclosed limitation. A high-level client's successful export
   must not be reported as selectable or tagged output without inspection.

4. **Build and capture settings change the evidence.**
   `crates/obscura-cli/Cargo.toml` has no default features. Source builds need
   `render` for screenshots, while the README describes multiple release
   variants. `crates/obscura-cli/src/main.rs` separates navigation timeout,
   adaptive settling, fixed waits, and a process-level hard deadline. Screenshot
   viewport dimensions are applied before navigation. Preserve those distinctions
   in receipts rather than claiming that a delay or output size proves readiness.

## Useful patterns retained

- Measure page-observed settings after applying emulation. A protocol method's
  acknowledgment is only transport evidence.
- Compare engines with the same page identity, fixture inputs, loaded resources,
  viewport, scale, scroll, and capture timing. Inspect geometry and reduce
  discrepancies to fixtures before adjusting tolerances or application code.
- Treat missing required content, including content omitted by snapshot
  truncation, as incomplete evidence. Exclude it from successful comparison samples.
- Refresh interactive references after navigation, tab changes, and DOM changes.
  `crates/obscura-mcp/src/lib.rs` keeps a snapshot-derived ref table and clears it
  on navigation and click paths. Its text output also explicitly marks truncation.
- Separate navigation/readiness deadlines from an outer process bound. Retain
  session isolation and state ownership independently of protocol compatibility.

The existing responsive helper already requires Chrome/Chromium, records
incomplete captures, bounds commands, preserves originals, and owns its process
cleanup. It remains unchanged. Native browser standards and accessibility
workflows retain their existing engines and verification requirements.

## Audit coverage and limits

Inspected the upstream skill, README, workspace and CLI manifests, security
policy, CLI fetch and timeout paths, CDP dispatch/emulation/PDF handlers, browser
PDF bounds, MCP state/interaction/HTTP paths, network URL and resolver guards,
related in-file tests, the MCP CORS integration tests, and PR workflow excerpts.
The network client validates URLs and redirects, filters resolved addresses,
and retains certificate validation on its inspected reqwest path. Private-network
exceptions and proxy behavior need task-specific egress verification. This audit
does not certify every transport or SSRF boundary.

The isolated Rust filter probe compiled the original `origin_allowed` function
without modification, used synthetic Origin strings, made no network requests,
and removed its temporary source and binary. The full engine was not built or
installed. Native suites, live CDP/MCP flows, render comparisons, benchmark
claims, V8 internals, stealth transport, and all vendored code were not executed
or exhaustively audited. There was no independent reviewer. No vulnerability
report or other message was sent upstream.

## Local implementation and provenance

Updated `cli-web-evidence` and its comparison reference, adding a conditional
backend-evidence reference. This is prose maintenance within the existing
browser selection and verification remit. It adds no installed browser, server,
new skill, capture backend, or invocation mode.

The upstream declares Apache-2.0 and contains separately licensed dependencies
and fonts. No upstream code, skill passage, asset, or license-bearing subtree
was imported into the collection. The isolated probe was disposable. The local
skill retains its original provenance and install targets. Any future binary
or source import must review that specific distribution and retain its required
notices. Upstream's instruction to preserve benchmark positioning is not adopted
as a restriction on honest local reporting.

## Local validation

Manual source walkthroughs: ignored media emulation requires an observed-state
check; a blank comparison image is incomplete; a stale element reference needs
refresh and post-action assertion; a tagged-PDF requirement cannot pass from
export success alone; a shared HTTP endpoint needs assigned ownership. Ordinary
Chromium responsive capture continues to use the existing harness.

`make check-fast` and `make check` passed: all 30 tests, provenance, portability
with ShellCheck, and installed links. The skill passed Skill Creator's quick
validator. These checks do not establish engine fidelity, performance
improvement, or live Obscura integration success.
