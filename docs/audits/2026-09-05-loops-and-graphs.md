## Decisions

| Concept | Local treatment |
| --- | --- |
| Checks that can reject bad work | Strengthen `verify-and-stop` with observable acceptance, relevant test selection, and disposable negative probes for suspect checks. |
| Dependency-based scheduling | Extend `git-hygiene`'s existing assignments with reasons for waits, including shared resources, ordering, and authority. No automatic delegation. |
| Repair the rejected unit | Return candidate identity, failure evidence, edit boundary, and recheck to its owner. Preserve accepted work and invalidate proof for affected dependencies. |
| Feedback into later work | Carry confirmed causes into pending briefs. Persist narrowly applicable guidance only within authorized maintenance. |
| Independent review contexts | Already covered by `code-review/references/independent-reviews.md`. No additional reviewer roster. |
| Mechanical processing | Use existing tools for exact comparisons. Semantic deduplication, ranking, and merge conflict resolution still need judgment. |
| Approval at the consequential action | Existing authority governs. Finish authorized preparation before requesting missing permission for the concrete remaining action. |

Reject the article's universal three-attempt diagnosis, the claim that every
dependency must pass a variable, and automatic promotion of every failure to a
permanent constraint. Retry limits bound effort, not causal reasoning. Required
integration checks remain necessary after individual units pass. Model confidence
cannot substitute for acceptance evidence or execution authority.

## Verification

Manual source walkthroughs, not independent agent executions:

- Three accepted units and one failed handler: the handler's receipt returns to
  its owner. Unchanged independent units remain accepted. A shared contract fix
  invalidates affected consumer evidence and requires integration checks.
- Two workers with no data exchange but one writable database: the resource
  constraint prevents concurrent mutation until isolation or ordering exists.
- A test command that selects zero relevant tests: its exit status cannot accept
  the requirement. A suspect check gets a disposable violating case.
- A verification-only request: failure is reported with evidence, not repaired.
- An accepted production candidate without execution authority: authorized
  preparation completes, but passing checks do not open the production action.
- A repeated failure: diagnose the evidence and reassess the assignment within
  a bounded retry policy. Preserve independent work and avoid global rule edits.
