# Ponytail audit

Audited on 2026-09-05 at
[`974d940a1c5344210874150b98ff0d2c861fab6a`](https://github.com/DietrichGebert/ponytail/tree/974d940a1c5344210874150b98ff0d2c861fab6a),
package version 4.9.0. Decision: retain useful ideas through locally written
refinements to existing architecture skills. Do not install the plugin bundle.

## Scope and findings

Read all six `skills/*/SKILL.md` entrypoints, the README and license, the Codex
manifest, lifecycle hooks and shared configuration/runtime/instruction builders,
statusline scripts, Pi and OpenCode adapters, MCP server and instruction helper,
and the published agentic benchmark report. This is an integration suitability
audit, not a complete security review of every installer, adapter, dependency,
or benchmark implementation. No upstream package installation was performed.

| Finding | Evidence at the audited revision | Decision |
| --- | --- | --- |
| Reuse deserves an explicit contract check before new structure. | `skills/ponytail/SKILL.md`, ladder and reading requirements. | Add concrete reuse candidates and semantic comparison to `codebase-design`. |
| Simplification findings should identify the replacement. | `skills/ponytail-review/SKILL.md` and `skills/ponytail-audit/SKILL.md`, categories of removable complexity. | Refine the existing architecture audit instead of adding overlapping review skills. |
| Known limits need a reason to revisit them. | `skills/ponytail/SKILL.md` and `skills/ponytail-debt/SKILL.md`, limit and upgrade conventions. | Use existing project debt/decision conventions, with an observable trigger. Avoid a new marker format and ledger. |
| The shortest solution can violate the requested contract. | Main skill's intensity examples substitute memoization for caching and let ultra mode decline a cache. Its rules also direct shipping a simplified version before questioning the request. | Preserve explicit requirements and compare expiry, isolation, and invalidation before accepting a cache substitute. |
| Review examples conflict with the main skill's safeguards. | Review recommends an at-sign check instead of an email validator and inlining a repository abstraction because it has one implementation. Its scoring rewards line removal. | Require behavior-preservation evidence. Consumer count and shorter code alone cannot justify removal. |
| Test guidance is too restrictive for this collection. | Main skill prescribes one runnable check and excludes frameworks and fixtures unless asked. | Keep repository-native verification. Fix a related local deepening instruction that treated replaced unit tests as automatically disposable. |
| Persistent activation overlaps every coding workflow. | Main description selects any coding task. `hooks/claude-codex-hooks.json` injects instructions at session and subagent start. Activation writes a mode flag and can emit a statusline setup request. | Retain existing skill selection. Install no hooks, modes, statusline configuration, or host rules. |
| Hook mode is shared across sessions using the same state directory. | `hooks/ponytail-runtime.js` has one `.ponytail-active` file, without a session key. Activation rewrites it from the default. | Reproduced in an isolated directory. A second session activation changes the first session's stored selection. Do not adopt this state mechanism. |
| The scoreboard is stale relative to the README. | `skills/ponytail-gain/SKILL.md` still presents the old single-shot reductions. README and `benchmarks/results/2026-06-18-agentic.md` explain the inflated baseline and report a different agentic result. | Import no scoreboard or performance promises. No benchmark was reproduced in this audit. |
| MCP adds runtime dependencies to serve static instructions. | `ponytail-mcp/index.js` returns the rules as a prompt/tool. Its package declares the MCP SDK and Zod. | Existing skill files already supply the relevant instruction surface. |

The benchmark report covers a limited model/task sample and explicitly says
the feature runs were not tested in a browser or server. Its safety checks
cover selected adversarial cases. Those results cannot establish general safety
or savings in this skill collection.

copies no upstream skill, script, asset, or instruction passage. The new prose
is locally authored, informed by the reviewed ideas and this repository's
existing contracts. The exact source revision and paths above preserve the
research trail without relabeling locally authored skills as Ponytail imports.

`UPSTREAMS.json`, generated `PROVENANCE.json`, per-skill `UPSTREAM.md` records,
and install targets retain their existing ownership. Any later import of
Ponytail material must preserve its applicable license and register its exact
source and local changes through the normal provenance workflow.

Both edited skills already resolve through managed installation symlinks to
this checkout. Their source edits therefore reach the installed collection
without installing a duplicate skill or changing links.

## Validation

- Executed an isolated hook reproduction using `CLAUDE_CONFIG_DIR` and
  `XDG_CONFIG_HOME` under a temporary directory. Started at full, selected lite
  for session A, then activated session B. The shared mode returned to full.
  No real client configuration was changed, and the temporary state was removed.
- `make check-fast`: passed for all 61 registered skills, including unchanged
  generated provenance.
- Manual source walkthrough: a TTL cache proposal must check expiration and
  tenant boundaries before accepting memoization. A single production adapter
  that isolates ownership remains a valid seam. A dependency with remaining
  consumers cannot count as removed. These checks exercise the written decision
  rules, not an independent agent execution.
- Invocation walkthrough: a known module redesign stays with `codebase-design`,
  a repository complexity survey stays with `improve-codebase-architecture`, and
  an ordinary defect investigation stays with `systematic-debugging`. Design
  and audit remain read-only unless implementation is authorized.
- `make check`: passed, including all 30 tests, portability with ShellCheck, and
  installed-link verification. The first sandboxed run could not create sockets
  for existing responsive-capture fixtures. The approved rerun with local socket
  access passed without source changes to those tests.
- Skill Creator's `quick_validate.py`: passed for both edited skills.
- Upstream benchmarks and live host integrations were not executed.
